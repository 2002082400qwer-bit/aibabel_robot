# Flash 与电机模块内存审查

审查日期：2026-10-09。按用户最新要求，仅检查 USER/Sourse/flash.c、mot1.c、mot2.c、mot3.c、motor.c，以及解释它们布局和字段类型所需的直接头文件、链接配置和现有 MAP/调用图。用户所写的 moter 对应本工程 motor.c。

结论：这五个模块的 Flash 地址分配和 RAM 静态分配合理，当前配置下未发现数组访问越界或 Flash 地址越界。电机位置计算仍存在极端数值下的溢出边界，应与内存地址越界分别看待。本次只更新审查记录，未修改五个模块的源码、头文件或链接配置，未编译或烧录。

依据为本轮重新读取的 RequirementDocument.md、当前五个源码及头文件，以及 2026-10-09 10:59:04 的 robot.map 和 robot.htm。芯片容量依据上一轮已经核对的用户手册与厂家 DFP：FT32F103VC 为 256KiB Flash、48KiB SRAM，页擦除单位为 2KiB。

上述数值包含三轴电机结构、任务结构和 PID 静态变量，不能再次把它们单独相加；不包含运行栈或被调用库函数的静态数据。flash.c 的静态 RAM 为零不代表函数执行时不消耗 RAM。

flash.c 的访问边界已经核对：

- 第 3 行的固定地址为 0x0803F800，按 2KB 页和 4 字节字对齐。robot_calibration.sct 把程序区限制为 0x08000000–0x0803F7FF；最后页 0x0803F800–0x0803FFFF 独占校准数据。
- 记录为 9 个 32 位字，共 36 字节。首字节地址为 0x0803F800，最后一个字起点为 0x0803F820，最后一个字节为 0x0803F823，距芯片末端仍有 2,012 字节。
- FlashCalibrationReadRecord()、读回校验和写入循环的记录下标均在 0–8；写入先覆盖下标 1–8，最后写下标 0 成功标记。CRC 读取下标 1–7，未访问数组以外位置。
- 三轴校准数组长度为 3；打包使用记录下标 2/3、4/5、6/7，CRC 使用下标 8。FlashCalibrationMotorCount=3 与当前 9 字记录布局一致。
- FlashCalibrationRead/Write() 对空指针和 motorMask 范围进行检查。motor.c 的调用方传入真实的 24 字节 FlashCalibrationData 局部结构，失败路径不会使用未完整加载的数据。
- 擦除只传入固定末页地址，编程地址也由固定起点和 0–8 的字序号计算；FlashInit() 仅锁定 Flash，不擦除。

motor.c 中保存和恢复三路结构字段时，校准数组下标均为 0–2；加载前先检查 CRC、版本、电机组合，再验证行程和换算关系。MOT1/MOT3 的最大行程先限定到 65535，当前换算系数也能容纳在 16 位字段中；MOT2 的最大行程限定到 0x0FFFFFFF，使验证中的 MaxPulseNum*10 保持在 32 位范围内。三轴停止、自检成功且无故障后才尝试保存，历史记录启动不会重复擦写。

mot1.c、mot2.c、mot3.c 没有变长数组、手动 RAM 地址写入、malloc 或基于脉冲数的指针偏移。位置、脉冲和 PID 结果均写入固定结构字段，因此下面的数值溢出不会直接将写地址移出结构边界。

仍需注意的数值边界：

1. mot1.c:464 和 mot3.c:455 将 PulseNum 直接累加回 16 位 CurPosition，再与 MaxPulseNum 比较。若 CurPosition=65530、PulseNum=10，写回的值会先回绕为 4，后面的最大行程判断无法恢复真实结果。两轴的 16 位 PulseNum 自增也会在超过 65535 时回绕。此项是接近类型上限时的位置/计数风险，未证明当前机械行程已触发。
2. mot2.c:528 使用 32 位 Height*PulseNumPerMm，但 motor.c:22–23 的校准上限主要保护 MaxPulseNum*10，未覆盖所有后续乘法。例：MaxPulseNum=50000000、PulseScale=980392 符合当前关系校验；Height=4500 也通过当前 5100 的高度上限。乘积为 4411764000，超过 32 位无符号上限，回绕后得到 116796704，后续位置计算会失真。这个例子是允许参数范围的边界模型，未模拟机械运动，也不代表正常标定值已发生溢出。

后续若要修复，可在较宽的中间变量中进行位置累加/乘法，按有效行程限幅后再写回；或把输入、校准上限收紧到所有后续表达式都安全的范围。当前未实施这些更改。

栈证据：FlashCalibrationRead 的可追踪调用深度为 80 字节，FlashCalibrationWrite 为 120 字节；从 MotorService 进入保存链的深度为 168 字节。三轴 MoveService 的可追踪深度分别为 88、72、88 字节，按顺序调用时不会把三个峰值简单相加。当前工程栈为 1KB，静态结果未显示本范围调用链超过栈容量；调用图仍存在未知路径，尚无实机水位记录，不能承诺所有运行组合均安全。

本轮运行现有 tests/motor_calibration.test.js，46 项通过，覆盖持久化和复位状态机。该测试是实际 C 源码转换后的主机模型，明确不模拟 C 整数溢出、Flash 硬件时序或机械行为。另通过 MAP 区间计算确认 225 字节静态区域全部在 SRAM 内且互不重叠，并用位宽模型验证上述数值回绕例子。没有把主机测试视为完整固件或实机证明。
